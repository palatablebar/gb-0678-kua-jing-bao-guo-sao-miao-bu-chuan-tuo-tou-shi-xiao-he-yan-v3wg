# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

## 本地时间与夏令时（DST）

标准批（10列）的 event_time 必须带UTC偏移，无偏移按 INVALID_TIME 隔离。本地补传批使用11列（追加 clock_offset），其 event_time 允许写承运商当地时间、不带偏移，由 app/dst.py 按目的地时区解释：

- 普通钟点唯一，直接定UTC（time_status=UNIQUE）。
- 秋季回拨日同一本地钟点出现两次（fold=0夏令时/fold=1标准时），产出两个UTC候选（AMBIGUOUS）。补传文件先后顺序（received_time）严禁用于消歧；只有 clock_offset 给出的显式UTC偏移可消歧，匹配成功转UNIQUE并记录采纳依据。
- 春季前跳不存在的钟点标记 SKIPPED 并隔离。
- 未消歧的歧义妥投不进正式时效：M4 出具 TIME_PENDING 临时路径（delivered_at 留空，保留两个候选及各自未采用原因），M5 时效挂起、不计赔付，仅按最晚候选给客服当天临时答复（最保守，避免把更晚签收误判达标）。
- clock_offset 取值如 -05:00、+09:00、Z；留空表示无显式偏移证据。

赔付结算走 /api/runs/<id>/claims 幂等登记，同一(批次,包裹)重试只生效一次；时效挂起件 settleable=false，返回409不可结算。原始扫描通过 /api/runs/<id>/raw 只读访问，任何重算或替换都不删除旧批次。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。
